# スキルのインストールコマンドの実装計画

2026-11-03 時点の実装計画である。対象は `install-skill` の追加、同梱スキルの作成、
ヘルプと README の注意メッセージの説明の修正、およびそれらのテストとする。

## 目的とコマンド

sumi の検査と改善プロンプトを Codex から使えるようにする。利用者の指定に従い、
インストール用のサブコマンド `install-skill` を追加する。依存は引き続き Rust の標準ライブラリだけとする。

```sh
cargo build --release --offline --locked
./target/release/sumi install-skill --target codex
./target/release/sumi install-skill --path .agents/skills/sumi
```

構文は `sumi install-skill --path <path>` と `sumi install-skill --target codex` の 2 形式とする。
通常の利用では `--target` でツールを指定する。現在の対応対象は `codex` とし、
そのユーザー用スキルディレクトリ `$HOME/.agents/skills` の下に `sumi` を置く。
未対応の対象名は、対応する対象名を示すエラーにする。対象名から配置先を決める処理と、
指定されたディレクトリにファイルを配置する処理を分け、両方のコマンド形式で配置処理を共有する。

`--path` はデバッグや独自の配置に使い、スキルを置くディレクトリそのものを指す。
相対パスは実行時の作業ディレクトリを基準にする。`--target codex` で `HOME` が未設定か空の場合は、
配置先の明示を求めるエラーを返す。`--path` は `HOME` の設定によらず動作する。
指定の省略、両形式の併用、指定の重複、他の検査・一覧フラグとの併用、余分な引数、空のパスは引数エラーとする。
インストール時は標準入力を読まずに処理する。

配置先は [Codex の公式スキル仕様](https://learn.chatgpt.com/docs/build-skills) の
ユーザー用 `$HOME/.agents/skills` とリポジトリ用 `.agents/skills` に合わせる。
従来の `$CODEX_HOME/skills` などを使う環境では `--path` にその環境の配置先を指定する。

## 配置するファイル

実行ファイル、スキル本文、MIT ライセンス本文を同じディレクトリへ配置する。

`SKILL.md` の原本はリポジトリの `skills/sumi/SKILL.md` に置き、`include_str!` で
バイナリへ埋め込む。実行ファイルは `std::env::current_exe()` が指すファイルをコピーし、
実行権限を保つ。実行ファイルに拡張子が付く環境では、その環境の実行ファイル名を使い、
スキル内の呼び出し例も合わせる。

バイナリは `SKILL.md` と同じディレクトリに直接置く。
インストール後は、読み込んだ `SKILL.md` の絶対パスから同じディレクトリの `sumi` を呼び出す。作業中の
リポジトリや `PATH` に同名コマンドがある場合も、同梱した実行ファイルを選ぶ。
元のチェックアウト、Cargo、ネットワークへの接続は、インストール済みスキルの実行に不要となる。
実行ファイルはコピー元と同じ OS・CPU 向けである。

## スキルが行う作業

スキル名は `sumi` とする。説明には、日本語の文章、Rust のコメント、HTML の本文にある
不自然な言い回しを検査し、依頼に応じて修正する用途を書く。明示的な `$sumi` の呼び出しと、
説明に合う依頼からの自動選択を使えるようにする。

本文には、同梱コマンドの場所、`--file` または標準入力での検査方法、言語の指定方法、
終了コードの意味を書く。終了コード 0 は検出なし、1 は検出あり、2 は実行エラーとして扱う。
検出時に出る改善プロンプトと提案を読み、依頼された範囲で意味と事実を保って書き直し、
再び検査する。検査だけの依頼では結果を報告する。誤検出や修正しても解消できない指摘は、
本文の意味を保ち、理由を報告して繰り返しを終える。

規則と改善プロンプトは既存の出力を使う。スキルには呼び出し方と結果の扱いを書き、
規則の一覧はバイナリが持つものを参照する。

## 既存ファイルとエラーの扱い

配置先が既に存在する場合は、空ディレクトリ、ファイル、シンボリックリンクのいずれも
エラーで知らせ、既存の内容を保つ。初回は必要な親ディレクトリを作り、配置先を新規作成する。
同じ場所への同時実行でも、配置先の新規作成に成功した処理だけが書き込む。

途中で失敗した場合は、その実行で作ったスキルのファイルとディレクトリを片付ける。
親ディレクトリは残す。片付けにも失敗したときは、残ったパスをエラーに含める。
プロセスの強制終了などで途中のディレクトリが残った場合も、次回は既存の配置先として扱う。

更新は、利用者が既存のスキルを退避または削除してから、新しい sumi で再実行する。
既存の内容を置き換える判断と操作は、利用者が行う。
成功時は配置先を標準出力へ英語で表示して 0 を返す。引数やファイル操作のエラーは、
既存の CLI と同じく標準エラー出力へ英語で表示して 2 を返す。

## テスト計画

| 対象 | 確認する結果 |
|---|---|
| `install-skill --target codex` | 子プロセスの `HOME` の下の `.agents/skills/sumi` にスキルを配置し、0 を返す。 |
| `install-skill --path <path>` | 相対パス、空白と日本語を含むパスに配置できる。`HOME` が未設定でも動く。 |
| 同梱バイナリ | `SKILL.md` の隣に実行ファイルがあり、別の作業ディレクトリから実行できる。自然な文、検出対象の文、不正な入力でそれぞれ 0、1、2 を返す。 |
| 引数 | 指定の省略・併用・重複、値の欠落、未対応の対象名、空のパス、余分な引数を 2 で拒否する。 |
| ホームディレクトリ | `--target codex` で `HOME` が未設定か空なら 2 を返し、配置先の明示を案内する。 |
| 既存の配置先 | ファイル、空ディレクトリ、既存スキル、シンボリックリンクを 2 で拒否し、既存の内容を保つ。 |
| 配置の失敗 | 親がファイルの場合は 2 を返す。ファイルのコピー失敗時は新規作成した配置先を片付け、親を残す。 |
| 注意の出力 | 標準入力と、言語を推定できるファイルの検査結果を確認する。言語を推定できないファイルは、検出ありの場合だけ注意を出す。通常出力では標準出力、`--check-only` と `--silent` では標準エラー出力に出す。 |
| ヘルプと文書 | `--help` と README の説明が注意の出力条件と一致し、両方のインストール形式が載る。 |

テストの出力先は一時ディレクトリに限定し、実際のユーザー用スキルディレクトリを保つ。
環境変数は子プロセスだけに設定する。コマンド全体の動作は `tests/cli.rs` の統合テストで確認する。
コピー失敗のテストは、テスト内で存在しないコピー元を渡して再現する。
そのテストは `src/install.rs` 内に置き、片付けを含む配置処理を直接呼び出す。

スキル本文は `skill-creator` の `quick_validate.py` で検証する。
次のコマンドで、書式、静的解析、追加したテストを含む全テスト、オフラインのビルドを確認する。

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo build --offline --locked
```

上記の検査が通り、両形式で配置したスキルの同梱バイナリが動作し、ヘルプと文書が
実装の挙動と一致した時点を、この計画の完了とする。

## 注意メッセージの説明の修正計画

- `--help` の説明を修正し、Markdown として読んだことを知らせる注意の対象を、
  言語を推定できないファイルに限定する。
- `README.md` に、言語を推定できないファイルを Markdown として読んだ場合でも、
  注意を出力するのは検出が 1 件以上の場合だけであることを明記する。
- `skills/sumi/SKILL.md` にも、同じ対象と出力条件を書く。

`src/main.rs` の注意メッセージの出力処理を現状のまま保つ。
`tests/cli.rs` で注意の出力条件を検証し、ヘルプ、README、スキルの説明が
その結果と一致することを確認する。
